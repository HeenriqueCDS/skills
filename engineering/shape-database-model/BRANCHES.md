# Database branches

One entry per branch, in interview order: each answer is an input to the next. Each gives what to **decide** and the **default** to recommend. Defaults assume PostgreSQL as the recommended engine; translate them when the user picks another.

## 1. Engine and version floor

- **Decide:** engine, the oldest major version you will run in any environment, hosting, and whether extensions are allowed.
- **Default:** PostgreSQL on a managed host, no extensions, so the schema moves between hosts unchanged. Record the floor precisely: features follow it (`uuidv7()` and virtual generated columns need PostgreSQL 18).

## 2. Tenancy and isolation

- **Decide:** one database per owner, one schema per owner, or a shared schema; and what stops a query from reading another owner's rows.
- **Default:** a shared schema with the owner id on every owned table. Composite foreign keys that include the owner id, so a child cannot point at another owner's parent. Add row-level security when a second database role or any ad-hoc SQL client exists, with `FORCE ROW LEVEL SECURITY` when the application role owns the tables (the owner bypasses it otherwise). Composite keys stop illegal links; row-level security stops illegal reads.

## 3. Entities and tables

- **Decide:** one table per entity, or one table for subtypes that are always read together.
- **Default:** one table per entity. Collapse subtypes into one table only for a single ordered scan, and then add `CHECK` constraints that forbid each illegal column combination.

## 4. Keys

- **Decide:** key type, who generates it, and which keys leave the database.
- **Default:** UUIDs when ids appear in the API, generated by the application as UUIDv7 so they stay time-ordered below PostgreSQL 18. `bigint` identity only for keys that never leave the database. A composite foreign key's target must be a primary key or unique constraint. PostgreSQL does not index the referencing side for you.

## 5. Types

- **Decide:** money, instants, calendar dates, time zones, closed sets.
- **Default:** `numeric` for plaintext money, never `money` (locale-dependent) or floating point. `timestamptz` for instants, `date` for calendar days, IANA zone names as `text` validated by the application. Enums only for sets that will never lose a value (enum values cannot be dropped). `text` plus `CHECK` for sets that will grow or shrink.

## 6. Database versus application enforcement

- **Decide:** for each invariant, whether the database holds it.
- **Default:** everything a single row or a foreign key can express lives in the database: `NOT NULL`, `UNIQUE` (including expression indexes such as `lower(name)`), `CHECK`, foreign keys. Cross-row rules, rules over encrypted values, and rules that need an external catalogue live in the application, listed with the reason. `CHECK` and `NOT NULL` cannot be deferred. `DEFERRABLE INITIALLY DEFERRED` is only for circular foreign keys.

## 7. Derived data

- **Decide:** store each computed value, or recalculate it at read time.
- **Default:** recalculate whatever the spec defines as derived from current data. Store a value only with a stated invalidation rule and a measured need.

## 8. Sensitive columns

- **Decide:** which columns the NFR classification requires encrypted, at which layer, the canonical plaintext, and how multiple values in one row are handled.
- **Default:** application-level AES-256-GCM on only what a dump must hide; one ciphertext per row, bundling values always read together; a random nonce, unique per key; additional authenticated data binding table, column, and primary key; a per-owner data key wrapped by a key held outside the database. Passwords are hashed, never encrypted. List every rule the database can no longer check (sign, range, sums). Disk encryption does not make a backup unreadable after key destruction.

## 9. Deletion

- **Decide:** hard or soft delete, cascade or block per relationship, and what account deletion must reach, including backups.
- **Default:** hard delete. `CASCADE` for owned rows. `NO ACTION` (not `RESTRICT`) for "blocked while in use", so deleting a whole owner still cascades in one statement. When the NFR promises backups become unreadable, the backed-up wrapped key must become unusable too; record how, or record the gap.

## 10. Auth and ephemeral state

- **Decide:** where refresh tokens, email tokens, idempotency keys, sessions, and rate-limit counters live.
- **Default:** a database table when the row must commit in the same transaction as a business write or survive a restart (refresh-token families, idempotency keys). Rate-limit counters in the gateway or process memory. A second store (such as Redis) means dual writes: justify it with the NFR's capacity numbers and cost ceiling.

## 11. Indexes

- **Decide:** one index per row of the access-pattern table, or an accepted sequential scan.
- **Default:** leading columns match the filter, then the sort. Partial indexes only when the query's `WHERE` matches the index predicate exactly. Expression indexes are used only by queries that repeat the expression. Ciphertext has no order, so encrypted columns are never indexed for range or sort.

## 12. Volume and scale

- **Decide:** users, rows per owner, rows one request reads (and decrypts), and the threshold that reopens the design.
- **Default:** one database node until one machine cannot take the load. Partitioning does not make one owner's full scan cheaper. Write the reopening number down.

## 13. Retention and purge

- **Decide:** what a scheduled job deletes, by which predicate, using which index.
- **Default:** an `expires_at` column plus an index for every ephemeral table. A rule that moves with time ("before the owner's current month") is written as its predicate, not faked as `expires_at`.

## 14. Evolution

- **Decide:** how breaking changes ship.
- **Default:** expand, migrate, contract. New indexes on live tables use `CREATE INDEX CONCURRENTLY`, which cannot run inside a transaction. Note schema choices that block deferred features (a unique owner id blocks "many per owner" later).
